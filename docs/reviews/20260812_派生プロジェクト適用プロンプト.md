## 作業 1: 全 SKILL.md のフロントマター検査（最重要）

`.claude/skills/*/SKILL.md`（および存在すれば `.claude/commands/*.md`）を**全件**開き、
以下の3点を検査して該当するものだけ修正する。テンプレート由来でない独自スキルも対象。

### 1-A. フロントマターの欠落

ファイル先頭が `---` で始まっていないスキルは、`description` が本文1段落目からの
フォールバックになり、Claude の起動判断が不安定になる。以下を先頭に追加する:

---
name: <ディレクトリ名と同じ>
description: <何をするスキルか。「いつ使うか」を先頭に書く>
---

テンプレート側では `.claude/skills/done/SKILL.md` がこれに該当した。修正後の姿:

---
name: done
description: 作業完了時に、決められたテーブル形式で完了報告を出力する。S/M/Lフローの最終ステップ。
---

注意: `done` に `disable-model-invocation: true` は**付けないこと**。
CLAUDE.md の S/M/L フローで Claude 自身が最終ステップとして実行するスキルであり、
これを付けると Claude から起動できなくなりフローが成立しない。

### 1-B. アンダースコア区切りのフロントマターキー

Claude Code のフロントマターは**ハイフン区切り**が正。
アンダースコア区切りのキーは不正キーとして無視される。

| 誤 | 正 |
|----|-----|
| `user_invocable` | `user-invocable` |
| `allowed_tools` | `allowed-tools` |
| `argument_hint` | `argument-hint` |
| `disable_model_invocation` | `disable-model-invocation` |

テンプレート側では `complete-feature/SKILL.md` に `user_invocable: true` があった。
ただし `user-invocable` の既定値は `true` なので、**書き直すのではなく行ごと削除**する。
そのうえで、ユーザーが明示的に呼ぶべき完了処理スキルであるため以下に置き換えた:

disable-model-invocation: true

このフィールドを付けてよいのは「**Claude が自律的に走らせると困るスキル**」に限る。
本プロジェクトでの判断基準:
- 付ける: 完了処理、リリース処理、破壊的操作を伴うもの
- 付けない: CLAUDE.md のフローで Claude が実行するステップになっているもの

### 1-C. SKILL.md 本文中の `$0` / `$1` / `$2`

これが最も実害が大きい。Claude Code は SKILL.md 本文の `$0` `$1` `$2` を
**スキル引数の置換プレースホルダ**（`$ARGUMENTS[0]` 等の短縮形）として展開する。
そのため、bash のつもりで書いた `$0` はコードブロック内であっても壊れる。

テンプレート側の `update-docs/SKILL.md` にあった実例:

git diff --name-only HEAD~${0:-1}

これは引数ありなら意図しない文字列に置換され、引数なしなら未置換のまま bash に渡り、
bash の `$0`（シェル名）が入って `HEAD~bash` になる。**どちらでも必ず失敗する。**

修正方針は、フロントマターで名前付き引数を宣言し、本文では `$名前` を使う:

（フロントマター）
argument-hint: "[遡るコミット数（省略時は1）]"
arguments: [depth]

（本文）
`$depth` に数値が入っていればその値を、空文字なら `1` を使って以下を実行する:

git diff --name-only HEAD~1

全スキルを `grep -rn '\$[0-9]' .claude/skills/` で走査し、
bash 変数のつもりで書かれている箇所をすべて洗い出すこと。

## 作業 2: フックスクリプトのコメント訂正

`.claude/hooks/*.js` に以下の趣旨のコメントがあれば、それは**現在は誤り**:

## 作業 1: permissions を .claude/settings.json（コミット対象）へ

まず現状を確認する:

- `.claude/settings.json` に `permissions` があるか
- `.claude/settings.local.json`（gitignore 対象）にしか無いなら、それが問題。
  複製・クローンした先に権限設定が一切引き継がれない状態になっている

チームで共有すべきルールを `.claude/settings.json` に移す。
`settings.local.json` にはそのマシン固有の緩和だけを残す。

### allow に入れるもの

**本プロジェクトの `package.json` の scripts を実際に読み**、開発で常用する
読み取り専用・冪等なコマンドだけを列挙する。テンプレートの内容を丸写ししない。
（例: `npm run build` が無いプロジェクトにその行を書かない）

目安: `Read` / `Glob` / `Grep`、`git status|diff|log|show|branch|add`、
ビルド・lint・型チェック、`prisma generate|validate`、プロジェクト固有の生成スクリプト。

### ask に入れるもの

取り返しはつくが影響が大きいもの: `git push`、`git reset`、`git checkout`、
`prisma migrate`、`prisma db push`。

重要: `git reset` を **deny にしないこと**。CLAUDE.md の「バグ修正の原則」で
「複数の仮説修正が失敗した場合は git reset でまとめて戻す」を推奨しており、
deny にすると自分のルールと矛盾する。ask が正解。

### deny に入れるもの

- `.env` 系の読み取り。ただし **`Read(./.env*)` の一括 deny は避ける**
  （`.env.example` まで読めなくなり、必要な環境変数の把握ができなくなる）。
  Next.js の命名規則に沿って個別に指定する:
  `Read(./.env)` `Read(./.env.local)` `Read(./.env.development*)`
  `Read(./.env.production*)` `Read(./.env.test*)`
- `Read(./secrets/**)` 等、プロジェクトに機密ディレクトリがあれば追加
- `Bash(rm -rf *)`
- `Bash(git push --force*)` `Bash(git push -f *)`
- `Bash(npx prisma migrate reset*)`

deny はどの設定レイヤーの allow よりも優先されるため、settings.local.json に
広い allow が残っていても deny は効く。

## 作業 3: フックに if 条件を付与

`.claude/settings.json` の hooks で、各 hook エントリに `if` を追加する。
`if` はパーミッションルール構文の公式フィールドで、
PreToolUse / PostToolUse / PostToolUseFailure / PermissionRequest / PermissionDenied で評価される。

これが無いと、Claude が `ls` を1回叩くだけでフックスクリプトが全数起動する。

  { "type": "command", "if": "Bash(git commit:*)",
    "command": "node .claude/hooks/pre-commit-type-check.js", "timeout": 120 }

`if` の値は、そのフックスクリプトが内部で判定しているコマンドと一致させること
（スクリプト内の正規表現を読んで確認する）。スクリプト側の判定は
二重防御として残す。timeout は**秒単位**。

## 作業 4: フックのブロック方式を見直す

フックスクリプトが `continue: false` + `stopReason` を返している箇所を洗い出す。
`continue: false` は **Claude を完全に停止させる**フィールドで、
「Claude に直してほしいだけ」の事象には強すぎる。

Claude に自己修復させたいもの（型エラー、lint エラー等）は以下に変更する:

  console.log(JSON.stringify({
    hookSpecificOutput: {
      hookEventName: "PreToolUse",
      permissionDecision: "deny",
      permissionDecisionReason: "型チェックに失敗しました。修正してから再度コミットしてください:\n" + out
    }
  }));

一方、**人間の判断を必ず挟みたいもの**（DB バックアップ失敗、本番系への操作）は
`continue: false` のままにする。テンプレート側ではこの非対称を意図的に残し、
両方のスクリプトのコメントに理由を書いた。同じ判断を本プロジェクトでも行い、
どちらにしたかをコメントに残すこと。

## 作業 5: スキルに allowed-tools を付与

## 作業 6: サブエージェントのツール制限

`.claude/agents/*.md` を全件開き、**そのエージェントの本務が書き込みを含むか**を
1件ずつ確認したうえで、助言・調査専門のエージェントだけ読み取り専用にする。

  tools: Read, Grep, Glob, WebSearch, WebFetch

テンプレート側で実際に検証した結果:

| エージェント | 判断 |
|-------------|------|
| product-advisor | 読み取り専用にできた（本文にも「実装は行わない」と明記されているが、実際には編集可能な状態だった） |
| code-reviewer | **制限不可**。レビュー結果を docs/reviews/ に保存し、重要指摘を自動修正する仕様 |
| browser-tester | **制限不可**。エビデンスフォルダへの report.md 保存が必須仕様 |
| documentation-manager / coding-specialist | **制限不可**。書き込みが本務 |

「本文に『書き換えない』と書いてあるから安全」は誤り。必ず本文を最後まで読み、
ファイル保存を指示している箇所が無いか確認してから制限すること。
制限したエージェントは実際に1回起動して、動作が壊れていないか確かめる。

また、特定 MCP しか使わないエージェントには以下を付けると、
他エージェントに不要なツール定義が載らずコンテキストを節約できる:

  mcpServers: ["playwright"]
